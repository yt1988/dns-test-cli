# 设计取舍

技术上为什么这样做，按日期倒序排列。网页版和 DNS 列表的取舍在 [yt1988/dns-test 的 docs/design.md](https://github.com/yt1988/dns-test/blob/main/docs/design.md)。

## 2026-11-05

- **超时没收到应答叫「无应答率」，不叫丢包**（v0.2.3 起）：UDP 查询没回应，可能是网络丢包，也可能是 DNS 服务器限速或丢弃了查询，从客户端分不出来。表头、图例（`!` 表示部分查询无应答，`×` 表示完全无应答）、`-v` 每行（`no-ans`）、帮助文字和 README 都用这个说法。JSON 字段名 `loss` 保持不变，免得用户的脚本出错；排名照旧按无应答率每 1% 慢 3% 计算。

## 2026-11-04

- **计数时数量放在名词后面**（v0.2.3 起）：「resolvers: 3 · rounds: 1」「lookups per resolver: 1」。这样 10 种语言都不用处理复数变化，比如俄语里 1、3、5 的写法各不相同。

## 一直以来

- **测法和网页一致**：按缓存命中查询的中位数排名，无应答率越高排名越靠后。未缓存的时间只显示，不参与排名：它取决于网站自己的 DNS 服务器在哪里，不是这家 DNS 的快慢。
- **列表跟着网页走**：运行时先取 dns.1ms.dog/resolvers.json，这样网页那边加一家 DNS，所有已装的工具都能马上用上。内置的那份是取不到时的后备，每天由 `resolvers` 工作流同步一次。
- **更新要核对**：自动更新会用 Release 的 `checksums.txt` 核对新的二进制。`--offline` 或 `DNSTEST_NO_UPDATE=1` 可以关掉更新检查。
- **安装和下载走 dns.1ms.dog 的转发**（`/i`、`/dl/`）：GitHub 在有些地方（比如中国大陆）很慢，或者连不上。
